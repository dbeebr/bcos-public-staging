# Schema — Teamcell Installation Receipt

Defines `.installation/TEAMCELL-INSTALLATION-RECEIPT.yaml`: the durable,
per-Cell record of what was installed, from where, in which mode, under which
governance and ownership configuration, and how to roll it back. The receipt
is the executed record of exactly what the confirmed preview displayed
(`docs/teamcell-install-semantics.md`).

## How a receipt is produced

1. `scripts/teamcell-install-preview.py ... --confirm --confirmed-by <id>`
   performs the install and writes `.installation/INSTALL-PREVIEW-MANIFEST.json`.
2. `scripts/generate-teamcell-installation-receipt.py <cell-path>` validates
   that manifest, reconciles the installed packages and every
   `files.created` / `files.changed` path against the tree, and writes the
   receipt. It refuses (writes nothing) if any check fails.

`files` lists what the install wrote from the kit and packages plus
`.bcos/CELL-GOVERNANCE.yaml`. Files generated afterwards —
`.installation/*` (manifest, closeout proof, receipt) and
`playbooks/onboarding/START-HERE.html` (regenerated by every
`scripts/start-cell.sh` run) — are not listed.

The generator never commits. Commit the receipt in the Cell like any other
change. In the public distribution there is no operator registry: when the
default registry file is absent, the generator skips the registry step.

## Terminology

- **`source`** — where the installed template kit came from, i.e. the
  distribution checkout that performed the install.
- **`source.clone_source`** — the concrete, existing Cell a
  `clone_existing_cell` install copied from. Non-null only in that mode.
- **Package provenance** — per-package origin, recorded in
  `installed_packages`. The top-level `source` describes the install event;
  `installed_packages` is the bill of materials.

## Object shape

```yaml
schema_version: "0.1"
installation_id: <stable unique id, e.g. INSTALL-YYYYMMDD-NNN>
installed_at: <ISO 8601 UTC timestamp>
installation_mode: new_from_template | hydrate_existing_repo | clone_existing_cell

source:
  repository: <owner/repo | local path>
  commit_sha: <40-character SHA — authoritative>
  version_label: <label | label+local-modifications | "unversioned">
  clone_source:
    repository: <owner/repo | local path> | null
    commit_sha: <40-character SHA> | null
    installation_receipt_ref: <path to the source Cell's own receipt> | null

target:
  repository: <owner/repo> | null
  path: <local path>

governance:            # snapshot of .bcos/CELL-GOVERNANCE.yaml
  governance_profile: quick_build | operating_team | compliance_safety | null
  legacy_unresolved: true | false
  cell_owner_role: <role-slug> | null
  decision_owner_roles: { <all ten classes>: <role-slug> | unresolved }
  role_bindings:
    <role-slug>: { human_id: human:<id> | null, display_name: <name> | null }

installed_packages:
  - package_id: <package id from packages/PACKAGES.yaml>
    source_repository: <owner/repo | local path>
    source_commit_sha: <40-character SHA>
    version_label: <label or "unversioned">

files:
  created: [<repo-relative path>]
  changed: [<repo-relative path>]

rollback:
  method: git_revert | git_reset_to_ref | manual
  ref: <branch/tag/commit> | null
  notes: <string>

preview_confirmed:
  confirmed_by: human:<id> | agent:<id>
  confirmed_at: <ISO 8601 UTC timestamp>

personalization:                # optional, additive; absent in receipts written before it
  status: generated | not_applicable
  generator: scripts/personalize-cell.py
  manifest: instructions/PERSONALIZATION-MANIFEST.json
  required_outputs: [instructions/PROJECT-INSTRUCTIONS.md, instructions/APP-INSTRUCTIONS-<app>.md]
  surfaces: [<app>, ...]
  cell_name: <string> | null
  cell_name_source: <string>
  repository: <owner/repo> | null
  unresolved: [{fact: <id>, where: <path>, reason: <string>}]
  reason: <string>              # required when status: not_applicable
```

## Field rules

### Identity and timing

- `installation_id` identifies the install event, not a work item.
- `installed_at` is when the mutation completed.
- `installation_mode` is exactly one of the three modes in
  `docs/teamcell-install-semantics.md`. Only `new_from_template` is validated
  in this public release; the other two are available, not validated.

### `source` (required)

- When installing from a clone of the public distribution, `repository` is
  that checkout's identity: its `origin` as `owner/repo`, or a local path if
  it has no `origin`. `commit_sha` is that checkout's `HEAD`.
- `commit_sha` is authoritative. `version_label` is a convenience and never a
  substitute; a label that cannot be reconciled to the SHA is a defect.
- `version_label` comes from `distribution/teamcell-lite/SOURCE-MANIFEST.json`.
  If the vendored kit's content hash does not match that manifest, the label
  gets the suffix `+local-modifications`. With no label, use `"unversioned"`.
- `clone_source` is non-null only when `installation_mode:
  clone_existing_cell`, and then records the concrete source Cell
  (`repository` and `commit_sha` both required). In every other mode all three
  sub-fields are `null`. When the source Cell's own receipt is available,
  `installation_receipt_ref` points to it so its lineage can be followed; when
  it is not, the field is `null` and lineage is recorded as unknown, never
  guessed.

### `target` (required)

`repository` is `owner/repo` if the Cell has or will have a remote, else
`null`. `path` is the local path the content was written to.

### `governance` (required)

A point-in-time copy of `.bcos/CELL-GOVERNANCE.yaml`, reproduced rather than
referenced so the receipt stays self-contained. `profile_recommendation` is
deliberately excluded — it is live, pending state, not installed state.

### `installed_packages` (required)

Exactly the baseline plus every selected optional package, including
auto-selected dependencies (`schemas/teamcell-package-manifest.schema.md`).
Each entry carries its own provenance. The generator refuses if the list and
the installed tree disagree in either direction.

### `files` (required, lists may be empty)

`created`: paths that did not exist before. `changed`: pre-existing paths the
install modified — only files explicitly approved in the preview, never
silent overwrites.

### `rollback` (required)

`git_revert` (revert the install commit), `git_reset_to_ref` (reset to the
recorded pre-install ref in `ref`), or `manual` (`notes` must describe the
procedure, e.g. deleting a freshly created directory).

### `preview_confirmed` (required)

`confirmed_by` is who explicitly confirmed the preview; `agent:<id>` is valid
only when the agent acted on explicit human instruction for this specific
install. `confirmed_at` must not be later than `installed_at`.

### `personalization` (optional)

The outcome of the installer's mandatory personalization step. With `status:
generated`, every `required_outputs` path and the `manifest` also appear under
`files.created` and exist in the tree, and the generator refuses to write a
receipt otherwise. The Cell's own check (`scripts/validate-cell.sh`) fails when
one of the required outputs is later removed. `unresolved` lists facts that
stay open (an unbound role, an undefined purpose); it never holds an invented
value. `not_applicable` needs a `reason` (for example modes that never generate
instruction files of an existing repository). Older receipts have no such
block; the Cell then gets a warning with the repair command instead.

## Consistency rule

The receipt must not record anything the preview did not show, and the
preview must not promise anything the receipt fails to record. A divergence
in files, governance or packages is an installer defect.

## Validation performed by the generator

- `installation_mode` is one of the three values.
- `source.commit_sha` and every `installed_packages[].source_commit_sha` are
  well-formed 40-character SHAs.
- `source.clone_source` follows the mode rule above.
- `governance_profile` is valid or `null`, and `null` iff
  `legacy_unresolved: true`; all ten decision classes are present.
- `rollback.method` is valid; `notes` is non-empty for `manual`.
- `preview_confirmed.confirmed_by` is present and `confirmed_at` ≤
  `installed_at`.
- Installed packages reconcile with the tree (see the package manifest
  schema).
- Every `files.created` / `files.changed` path exists in the installed tree.
- When `personalization.status` is `generated`: `required_outputs` is a
  non-empty list that includes `instructions/PROJECT-INSTRUCTIONS.md`; each
  entry and the manifest exist and are listed under `files.created`.

## Example (illustrative, not a default)

```yaml
schema_version: "0.1"
installation_id: INSTALL-20260714-001
installed_at: "2026-07-14T12:00:00Z"
installation_mode: new_from_template
source:
  repository: example-org/bcos
  commit_sha: "0123456789abcdef0123456789abcdef01234567"
  version_label: v1.0.0
  clone_source: { repository: null, commit_sha: null, installation_receipt_ref: null }
target:
  repository: example-org/example-cell
  path: /home/example/example-cell
governance:
  governance_profile: null
  legacy_unresolved: true
  cell_owner_role: null
  decision_owner_roles: { routine_work: unresolved, ... }   # all ten, unresolved
  role_bindings: {}
installed_packages:
  - package_id: teamcell-lite-baseline
    source_repository: example-org/bcos
    source_commit_sha: "0123456789abcdef0123456789abcdef01234567"
    version_label: v1.0.0
files:
  created: [README.md, PROJECT.md, TEAM-PROFILE.md, .bcos/CELL-GOVERNANCE.yaml]
  changed: []
rollback:
  method: manual
  ref: null
  notes: "New target with no prior history — delete the directory to roll back."
preview_confirmed:
  confirmed_by: human:example-lead
  confirmed_at: "2026-07-14T11:58:00Z"
```
