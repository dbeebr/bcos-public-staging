Drei Skills. Drei echte Aufgaben. Direkt ausprobieren.

Business Analyst, Requirements Engineering und Team Event Planner sind installiert und einsatzbereit. Diese Seite zeigt in unter 60 Sekunden, wie ihr sie in VS Code mit echtem Repo-Kontext ausprobiert — und wie ihr sie sicher weiterentwickelt, ohne Evidence-, Human-Gate- oder Nicht-Autoritäts-Regeln zu verwässern.

So probiert ihr einen Skill in VS Code aus

  1. Use Case unten wählen und den vollständigen Prompt kopieren.
  2. VS Code im Cell-Repo öffnen (mit vollem Repo-Kontext, nicht in einem leeren Chat).
  3. Prompt an euren Agenten (z. B. Claude Code, Codex) einfügen und ausführen.
  4. Den gerouteten Artefakt-Ort prüfen: work/, human-gates/, history/learning-candidates/, ein Completion Record oder ein Cell Update.
  5. Ergebnis mit dem "Expected result"-Abschnitt der Karte abgleichen.
  6. Beobachtung machen? Weiter zu Skill verbessern — nicht direkt die Skill-Datei editieren.

Drei echte Use Cases

Requirements Engineering

Kündiger Self-Service-Strecke mit Angebotssteuerung

Was der Skill tut: verwandelt eine bereits akzeptierte Entscheidung in eine testbare, rückverfolgbare Spezifikation. Was der Skill nicht entscheidet: ob die Strecke überhaupt gebaut wird, und keine kommerziellen Angebotswerte (Bonushöhe, Berechtigungsschwellen, Freigabe) — das bleibt bei einem Menschen.

Vollständiger Copy/Paste-Prompt (Deutsch)

Ohne JavaScript: Feld anklicken, markieren, kopieren.
Expected result — was passiert danach?
May create
A work/ WorkItem holding the requirements spec; a human-gates/ HumanGate if retention-offer economics are undecided.
Human still decides
Which accepted decision authorizes this work; any commercial offer values, thresholds, or approval.
Evidence the agent must cite
The accepted source reference; any constraints already on record.
Good result looks like
Every requirement has a stable REQ-<slug>-NNN ID traced to the accepted source and a testable acceptance criterion; the "Open conflicts" section is present even if empty; no invented commercial values.

Common wrong turn: picking a plausible bonus/discount value or eligibility threshold "to make it concrete" instead of naming it as an open conflict routed to a Human Gate.

Business Analyst

Tarifwechsel-Prävention vor Vertragsablauf

Was der Skill tut: verwandelt eine unscharfe geschäftliche Frage in eine entscheidungsreife Analyse mit Evidenz, Optionen und Trade-offs. Was der Skill nicht entscheidet: ob eine Maßnahme umgesetzt/finanziert wird — das bleibt beim Decision Owner.

Vollständiger Copy/Paste-Prompt (Deutsch)

Ohne JavaScript: Feld anklicken, markieren, kopieren.
Expected result — was passiert danach?
May create
A work/ WorkItem holding the analysis (always — routine or fork alike); additionally, a human-gates/ HumanGate when the analysis surfaces a genuine strategic fork.
Human still decides
Whether a recommended treatment is approved/funded; any strategic fork the analysis names but can't adjudicate.
Evidence the agent must cite
A source reference for every "Evidence" line; existing Cell artifacts it actually read.
Good result looks like
At least two genuinely distinct options with trade-offs; Evidence and Hypothesis visually separated; ends in exactly one of a recommendation or a Human Gate, never both, never neither.

Common wrong turn: recommending an intervention with an invented uplift or sample-size number instead of citing real data or naming the gap as a hypothesis.

Team Event Planner

Roadmap-Alignment plus Teambuilding

Was der Skill tut: entwirft ein fertiges Moderationsdesign für ein Team-Meeting. Was der Skill nicht entscheidet: er terminiert nichts, lädt niemanden ein, bucht nichts und gibt nichts aus — das bleibt immer eine menschliche Aktion.

Vollständiger Copy/Paste-Prompt (Deutsch)

Ohne JavaScript: Feld anklicken, markieren, kopieren.
Expected result — was passiert danach?
May create
A pre-event work/ WorkItem holding the design; after the event, a CellUpdate or CompletionRecord if warranted.
Human still decides
The objective, if contested; actually scheduling, inviting, booking, or spending anything.
Evidence the agent must cite
Only already-on-record participants and constraints — never invented preferences or availability.
Good result looks like
Every participant has a stated decision role; accessibility accommodations are concrete, not boilerplate; the explicit non-actions line is present verbatim.

Common wrong turn: drafting an actual calendar invite or a message to send to participants, or writing "we'll make sure it's accessible" with no concrete accommodation.

Skills are selected by trigger, not all loaded at once. Start at apps/team-capability-pack/CONTEXT_INDEX.md, match your request to exactly one routing-table row, and load only that one skill file. If your request spans more than one skill, load the first one only — its output routes to the next skill as a separate step.

Skill verbessern — improve safely, don't rewrite on feel

Don't edit a skill just because one output felt imperfect. A single observation is a data point, not a mandate. Follow this loop instead:

real use -> inspect output against contract -> evidence-backed observation -> LearningCandidate -> classify exact delta -> test against existing proofs -> reviewed local adaptation OR upstream version proposal

Procedure truth

The canonical skill contract itself — apps/team-capability-pack/skills/*.skill.md. Never edited on a feeling; only via a reviewed decision.

Team-local vocabulary / examples

Cell-specific terms, examples, or narrow adaptations layered on top of procedure truth — scoped to this Cell, never silently overwriting the canonical file.

Learning candidate

A non-canonical, human-gated observation buffer at history/learning-candidates/. Status progresses candidate → observed_once → repeated → ready_for_bcos_review. No BCOS repository mutation is ever triggered directly from an entry here.

Canonical promotion / version change

Only happens after a human reviews a repeated, evidenced pattern and explicitly accepts a version change to the upstream template or BCOS adapter — never automatically from one run.
