What Is This Workspace?

Teamcell Lite is a lightweight shared operating layer for a team or cross-functional cell. It gives everyone — humans and AI agents — a single, structured place to manage work, record decisions, and hand off context.

It is not a replacement for your existing tools. Your ticketing system, wiki, design tool, and source control remain authoritative for the things they own. Teamcell Lite sits alongside them as a coordination surface.

What it is:

  • A local, file-based operating layer
  • A shared context for humans + agents
  • A structured inbox → work → decision flow
  • A lightweight governance record

What it is not:

  • A replacement for your ticketing system
  • A content management system
  • A live application or hosted service
  • An autonomous decision-maker
Your authoritative systems (ticketing, wiki, design tool, source control) stay where they are. This workspace references them — it does not replace them.

The Five Surfaces

Every Teamcell Lite workspace contains the same five top-level areas. Each has a defined role.

Surface What it holds Who adds to it
inbox/ Raw inputs that haven't been processed yet — notes, summaries, requests, exports from other tools Anyone (human or agent)
work/ Active work items created from inbox inputs or templates Humans (agents assist)
human-gates/ Decision points that require explicit human sign-off before proceeding Humans only — agents may draft, never approve
history/ Completed or archived items; immutable record Moved here when work closes
playbooks/ Repeatable process guides and templates Team members; updated deliberately
Skills (AI capabilities) may be introduced later as an optional layer — they are not required for a basic Teamcell Lite setup.

Human vs Agent Responsibilities

Teamcell Lite is designed around a clear boundary: humans own decisions; agents handle drafting, scanning, and structuring.

Humans own:

  • All human-gate approvals
  • Decisions that affect live systems or people
  • Committing changes to source control
  • Adding confidential inputs to the workspace
  • Final review and sign-off

Agents assist with:

  • Drafting work items from inbox inputs
  • Scanning for gaps, risks, or inconsistencies
  • Structuring notes into templates
  • Summarising context across surfaces
  • Suggesting — never deciding
Agents in this workspace are advisory-only. They do not have autonomous write access to live systems. Every consequential action requires a human to confirm and execute.

This boundary is enforced by workspace configuration, not just convention. Human-gates exist specifically to make the boundary visible and auditable.

First Safe Use Cases

Start with low-risk, read-heavy tasks. These patterns are safe to try on day one:

Use case How it works
Story / readiness review Drop a requirements document or story into inbox/. Ask an agent to scan it for gaps or missing acceptance criteria.
Requirement → test ideas Agent drafts candidate test scenarios from a requirement. Human reviews and adapts before adding to test plans.
QA risk scan Agent reviews a change description and flags risk areas. Human decides what to act on.
Design-system consistency review Agent checks a component spec against stated design-system guidelines. Human validates findings.
Meeting notes → work item Paste meeting notes into inbox/. Agent structures them into a draft work item. Human refines and files.
Human gate capture Create a gate entry when a decision point is reached. Record who approved and when.
All of these keep humans in the loop at each step. Nothing is committed to live systems without explicit human action.

Data Policy

Teamcell Lite workspaces are typically stored in version-controlled repositories. Follow these rules at all times:

Never commit the following to this workspace:
  • Secrets, passwords, or credentials of any kind
  • Private keys, tokens, or API keys
  • Unapproved confidential business content
  • Personal data (names, emails, addresses) unless explicitly approved for this workspace
  • Customer or HR data unless explicitly approved
  • Content copied from third-party systems without authorisation

These rules apply to all workspace surfaces: inbox/, work/, human-gates/, history/, and playbooks/.

What belongs here: synthesised summaries, structured work items, decision records, process guides, and references to external sources — not the raw confidential source content itself.

If your organisation has a data classification policy, apply it before adding anything to the workspace. When in doubt, ask your workspace owner.

First Setup Steps

When you receive a new Teamcell Lite workspace, read these files in order before doing anything else:

  1. README.md — workspace overview and purpose
  2. PROJECT.md — current project scope and objectives
  3. TEAM-PROFILE.md — team context, roles, and conventions
  4. AGENTS.md — which agents are configured and what they can do
  5. CONTEXT_INDEX.md — index of key context files

Then follow this flow for your first work item:

1. Add raw input to inbox/
   (a note, export, or summary — no secrets)

2. Create a work item from a template in work/
   (or ask an agent to draft one from the inbox item)

3. Review and refine the work item
   (agent output is a starting point, not a final result)

4. If a decision is needed, create a human-gate entry
   (human approval required before proceeding)

5. When complete, move the item to history/

6. Run the workspace validator to check structure:
   sh scripts/validate-cell.sh .
The validator catches structural issues early. Run it after any significant change to the workspace.

Install / Setup: Get the Team Cell on your computer

Prerequisites:

  • Access to the GitHub repository (ask your team lead)
  • VS Code installed
  • GitHub Desktop is the easiest path for most users
  • Terminal is optional
  • Claude Code / Claude CLI is optional, not required

Mac

Option A — GitHub Desktop:

  1. Open GitHub Desktop
  2. Clone the Team Cell repository
  3. Choose a local folder
  4. Open it in Visual Studio Code

Option B — Terminal:

git clone <repo-url>
cd <repo-folder>
code .

Windows

Option A — GitHub Desktop:

  1. Open GitHub Desktop
  2. Clone the Team Cell repository
  3. Choose a local folder
  4. Open it in Visual Studio Code

Option B — VS Code:

  1. Open VS Code
  2. Choose "Clone Repository"
  3. Paste the repository URL
  4. Choose a local folder
  5. Open the repository
Optional — Agent path (Claude Code / Claude CLI users only): If you already use Claude Code, open the Team Cell folder in Terminal and start Claude there. The agent will use AGENTS.md, README.md, and CONTEXT_INDEX.md as working context.
